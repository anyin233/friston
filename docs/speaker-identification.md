# 说话人识别：音色 + 方位 + 预录声纹

目标：实时字幕里直接显示“谁在说话”，会后再做一次精细修正。

## 三类证据

| 证据 | 来源 | 作用 | 局限 |
| --- | --- | --- | --- |
| **流来源** | 麦克风 vs 系统声音（ScreenCaptureKit / Core Audio process tap） | 硬分区：远程参会者的声音只来自系统声音，不会和会议室里的人合并 | 系统声音里的多个远程人员仍要靠音色区分 |
| **音色** | Sortformer 流式分离（每 480 ms 更新，最多 4 人）+ WeSpeaker ResNet34（256 维）或 CAM++ 声纹向量 | 主要信号；还能和预录声纹比对，直接叫出名字 | 短句、重叠发言、音色相近的人会混淆 |
| **方位** | 多声道麦克风上的 GCC-PHAT 时延估计 → 方位角 | 区分音色相近但坐在不同位置的人；让短句的归属更稳定 | 需要 ≥2 个**真实**麦克风声道；只在单场会议内有效 |

## 融合规则（`native/NativeKit/Sources/MeetingCore/SpeakerFusion.swift`）

1. 先与预录声纹比较，余弦相似度 ≥ 0.62 就直接标为这个人。
2. 否则只和**同一流来源**的匿名簇比较：
   `score = cos(音色) + 0.25 × 方位置信度 × (2·exp(−(Δ角/30°)²) − 1)`
   方位最多加分或减分 0.25：同一方向加分，相差 120° 时减分。
3. 分数 ≥ 0.55 加入已有簇，否则新建“说话人 N”。
4. 簇中心随新观测更新；方位用指数滑动平均，人在座位上挪动也能跟上。
5. 方位**不写入声纹**，因为人每次开会都可能换座位。

单元测试覆盖了三种情况：不同的人得到不同的簇；音色相近（余弦 0.6）但方位相差 120° 时被分开，没有方位信息时则会合并；预录的人被直接命名，并且系统声音与麦克风之间不会跨源合并。

## 预录声纹（用户提前定义部分说话人）

两种方式（见原型的“说话人”页）：

1. **专门录制**：朗读一段覆盖常见音素的文字，凑够 15 秒有效语音。实时检查：是否只有一个人在说、信噪比、有没有回声。
2. **从录音中截取**：在任意历史录音的波形上框选一段，参考下方的说话人分段，选干净的单人片段。

另外，会后在字幕里给“说话人 4”命名，会把这个簇的声纹存为该人物的新样本（来源记为“会后确认”），之前的发言也一起改名。

每人可以有多段样本，来自不同麦克风或房间；比对时取各样本中的最高分。声纹向量存在 `voiceprints` 表，并标注模型名，不同模型的向量不会互相比较。

## 这台 Mac 上的硬件实情（2026-11-05 实测）

| 设备 | 声道 | 能否判断方位 |
| --- | --- | --- |
| MacBook Pro 内置麦克风 | **1**（系统已做波束成形） | 否，只能靠音色 |
| XREAL One Pro | 2（USB） | 可以，能分辨左右前方的半平面 |
| WeMeet Audio Device（腾讯会议虚拟设备） | 2，但 transport 是 virtual | **否**，已在探测代码中排除 |
| AirPods | 1 | 否 |

结论：
- 内置麦克风阵列在 Core Audio 层只暴露 1 个声道，**做不了基于位置的识别**。AVFoundation 的 FOA（一阶 Ambisonics）模式在本次探测中显示不支持，但探测进程当时没有麦克风授权，需要在已签名 App 中重新确认（见 tech-stack.md 的“待验证”）。
- 要用方位识别，需要外接 ≥2 声道的麦克风：USB 会议阵列、立体声麦克风，或 XREAL 这类双麦设备。双麦线阵**前后不可分**，只能得到 −90° 到 +90° 的方位角，界面上的会议桌也只画前方半圆。
- XREAL 这类**头戴设备**：方位是相对头部的，转头会让所有人的方位一起偏移。后续要加整体偏移校正，例如以“我”的声音和稳定说话人作为参照。
- 没有多声道设备时，系统自动退化为“流来源 + 音色”，功能照常可用。

## 会后精修

会议结束后，用 Qwen3-ASR 1.7B、ForcedAligner 和离线分离（Pyannote 或 Sortformer）对整段录音重算一遍，再全局重新聚类，修正实时阶段的误判。重叠发言段落会标出来，供用户复核。
